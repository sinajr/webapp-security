Demo 5: security misconfiguration (DEBUG = True)

Django's debug page is one of the best debugging tools in any web framework. When an unhandled exception happens and DEBUG = True, Django replies with a page containing the full stack trace, the value of every local variable in every frame, the list of installed applications, your URL configuration, the request headers, the session contents and a dump of your settings. That is exactly what you want on your laptop, and exactly what an attacker wants on your production server.

Right now DEBUG = {{ debug_mode }}, because this lab ties DEBUG to the SECURE_MODE switch.

What else DEBUG = False turns on

  • ALLOWED_HOSTS starts being enforced, which blocks Host-header poisoning (poisoned password-reset links, cache poisoning).
  • Django stops recording every SQL query it runs in memory, which is both a memory leak and an information leak.
  • Static files are no longer served by the development server, which forces you to set up a real static-file setup instead of shipping one.

The deployment checklist

You do not have to remember all of this. Django ships a checker that reads your settings and tells you what is wrong: 

python manage.py check --deploy

Run it in both modes and compare. In vulnerable mode it will complain about DEBUG, about the missing SECURE_HSTS_SECONDS, about SESSION_COOKIE_HTTPONLY being off, and about the hard-coded SECRET_KEY. A real deployment should produce no warnings at all before it goes live.

A few warnings remain even in secure mode, and they are worth understanding rather than silencing. The HTTPS-related ones (SECURE_SSL_REDIRECT, SECURE_HSTS_SECONDS, SESSION_COOKIE_SECURE, CSRF_COOKIE_SECURE) stay because this lab runs over plain HTTP on localhost; on a real site served over HTTPS you must switch them on, since a "secure" cookie is one the browser refuses to send over an unencrypted connection. The SECRET_KEY warning stays because we hard-coded an insecure key in settings.py - which is itself a misconfiguration a real project must not ship. A clean production run of this check should report zero warnings.
